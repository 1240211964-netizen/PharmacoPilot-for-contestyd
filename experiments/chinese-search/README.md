# FTS5 中文检索技术探针(experiments/chinese-search)

独立技术探针,验证 `node:sqlite` FTS5 对中文教学/政策文本的检索能力,为"未来业务检索采用哪条通道"提供实测依据。**完全独立运行**:仅用 `:memory:` 库,不碰 `.pharmaco-data/`,不依赖 `server/`,零 npm 依赖(分词用 Node 内置 `Intl.Segmenter`)。设计依据:`docs/product-core/retrieval-probe-design.md`(v1.0.0 草案)。

## 运行方法

```bash
node experiments/chinese-search/build-corpus.mjs     # 校验语料/查询/金标准契约
node experiments/chinese-search/build-indexes.mjs    # 建四种索引(:memory:),打印索引大小
node experiments/chinese-search/run-evaluation.mjs   # 一次跑通评测,生成 results/
```

`run-evaluation.mjs` 输出 `results/results.json`(全量结构化指标)与 `results/report.md`(逐题明细报告)。`node:sqlite` 的 ExperimentalWarning 属正常输出。本探针不进 `npm test`(`server/*.test.mjs` 约定不适用)。

## 四通道设计

| 通道 | 方案 | 查询侧 |
|---|---|---|
| A | FTS5 `unicode61` 原始文本(title+text) | 原文短语查询 |
| B | FTS5 `trigram` 原始文本(content_raw) | 原文短语查询(等价子串匹配;<3 字查询结构性返回空) |
| C | `Intl.Segmenter('zh',{granularity:'word'})` 预分词、空格连接入 `unicode61`(content_segmented) | 查询同样分词,词元 `OR` 连接,bm25 排序 |
| D | B + C 双通道 **RRF 融合**:**k=60,两通道等权(1:1),候选深度各 top-50**,固定参数未调参 | B、C 各取候选后按 `1/(k+rank)` 求和 |

另有**结构过滤路径**(不走全文):对 stageId(S1-S9)/标签(OBE/UBD)/条款号(第十二条)/文件编号(药监发〔2023〕15号)类查询,直接对 `docs` 元数据字段做 SQL 精确过滤(并对文本 LIKE 做对照),与全文通道记录互补情况。

## 语料与查询

- **语料 31 篇**:teaching 6(抽取自 `shared/station*.payload.js` 真实教学负载)、textbook 10、policy 8(编号全部虚构脱敏)、rubric 3、case 4(虚构脱敏)。字段:`{docId,title,sourceType,text,meta?}`。
- **查询 35 条**(有答案 29,无答案 6):覆盖两字词/多字词/英文缩写(S1、OBE、UBD、TDM)/条款号/文件编号/词形近似/同义字不同/跨表达/长问句/极短(1 字)/无答案。同义题不硬编码同义词映射,允许词法通道失败。
- 金标准 `gold.json`:`{queryId,relevantDocIds[],answerable}`。

## 结论摘要(2026-08-03 实测)

核心指标(有答案题 29 条;索引大小为 dbstat 实页字节,源文本 10444 B):

| 通道 | Recall@5 | Recall@10 | MRR | 无答案误召回率 | p50 延迟 | 索引大小 |
|---|---|---|---|---|---|---|
| A unicode61 原始 | 0.310 | 0.310 | 0.310 | 0 | 0.024 ms | 45056 B |
| B trigram 原始 | 0.448 | 0.448 | 0.448 | 0 | 0.028 ms | 69632 B |
| C 分词+unicode61 | **0.966** | **0.966** | **0.966** | 0.667 | 0.057 ms | 53248 B |
| D RRF(k=60 等权) | **0.966** | **0.966** | **0.966** | 0.667 | 0.089 ms | 122880 B |

主要发现:

1. **通道 A 对中文连续文本如预期退化**:整句成一个词元,纯中文查询基本全灭;仅对含 ASCII/数字结构的查询(S1、OBE、文件编号)和政策排版惯例"第X条␣"后的条款号有效。R@5=0.31 即为"不分词有多差"的量化基线。
2. **通道 B(trigram)≈ 子串匹配**:≥3 字且逐字出现的查询全中;但 **<3 字查询结构性返回空**(学情/评价/首剂/S1 全灭,这是 trigram 分词器硬限制,非语料问题);错别字、同义、换措辞、长问句全部失败。误召回率 0 是"宁可不答"的假象。
3. **通道 C(分词)是词法通道的最优解**:29 条有答案题仅失败 1 条(q17"剂最",2 字错词无任何通道能救)。短词(≤2 字)除该错词外全部通过。
4. **C 的代价是无答案误召回率 0.667**:查询侧词元 OR 语义下,无答案长查询会因共享词元(如"药物""设计")捞回噪声 top-5。业务化时必须在通道之外加门禁(bm25 分数阈值/答案判定点),而不是换通道。
5. **D(RRF)本语料上与 C 持平、零新增召回**:B 的有效召回全部是 C 的子集,D 的价值仅是"B 失败时 C 兜底"的冗余保险;等权 RRF 未拉伤 C 的排序,但索引成本翻倍(122880 B vs 53248 B)。在小语料上 D 无收益,保留为可选。
6. **结构过滤验证成立**:S1 类查询 B 通道全灭(2 字符硬限制),元数据路径 2/2 精确命中;条款号/文件编号类全文通道虽能命中,元数据路径提供了无歧义、无排序风险的精确保险。**结论与设计一致:结构标识走元数据过滤,语义走全文(C 通道),两者组合**。
7. **同义题的真实边界**:"药物不良反应"(语料为"药品不良反应")被 C 靠共享词元("不良""反应")OR 捞回——属侥幸而非能力;若同义表达零共享字,词法通道必然失败,这是留给语义通道的问题,本探针不做同义词硬编码。
8. 索引体积在此微型语料上被 SQLite 页开销主导(每通道 5-6 张子表 × 4 KB 页),A/B/C 分别为源文本的 4.3/6.7/5.1 倍,绝对值无意义,仅记录相对关系:trigram > 分词 > unicode61。

### 已知边界

- 语料 31 篇、单轮跑分,数值只用于通道间相对比较,不外推绝对水平。
- C 通道查询侧用 OR;若改 AND 会提升精度但伤害长问句召回,未探索(属调参,按设计纪律不在本轮做)。
- 全部查询为单线程同步执行,延迟仅作相对参考。
