# 中文检索探针设计(FTS5 四通道)

- 版本:v1.0.0
- 日期:2026-08-03
- 状态:草案

本文是 `experiments/` 下 FTS5 中文检索技术探针的设计。探针**不进入业务依赖**;FTS 表即使建立也只是**派生索引,不是事实源**(事实源是 `asset_versions` + `content_blocks`)。运行数据(pretest_responses / runtime_observations)不进检索索引。

## 1. 四个通道

| 通道 | 方案 | 说明 |
|---|---|---|
| A | FTS5 `unicode61` 默认分词 | 基线;预期对中文连续文本退化(整句成词),用于量化"不分词有多差" |
| B | FTS5 `trigram` | 中文连续文本的零依赖兜底;预期召回高、噪声高 |
| C | **`Intl.Segmenter('zh',{granularity:'word'})` 预分词 + FTS5**(unicode61,以空格连接分词结果入库) | Node 内置,零依赖;优先实现 |
| D | trigram + 分词**双通道 RRF 融合** | B、C 各自取候选,按 RRF 融合排序 |

### 通道 C 的精确结构过滤

带精确结构的查询成分**不走全文,走 SQL 元数据过滤**,再与全文通道结果求交/加权:

- stageId(`S1`-`S9`);
- 知识体系标签(OBE、UBD 等);
- 条款号(如"第十二条")、文件编号(如"国药监注〔2020〕12 号")等结构化标识。

理由:这类成分在全文索引里区分度差且易误配,而它们在 `knowledge_assets` / `content_blocks` 元数据上是精确字段。探针需验证"结构过滤 + 全文召回"组合优于纯全文。

## 2. 测试查询集要求

查询集覆盖以下类型(每类至少 2 题,与 `evaluation-dataset-design.md` 的 retrieval 集共用):

1. 两字词(如"首剂");
2. 多字词(如"治疗药物监测");
3. 英文缩写(如"TDM"、"PK");
4. 条款号(如"第十二条");
5. 文件编号;
6. 词形近似(如"剂量"vs"剂最"、漏字/多字);
7. 同义字不同(如"血药浓度"vs"血浆浓度")——**允许 v1 失败,不硬编码同义词表**,如实记入短词/同义失败清单;
8. 无答案题(语料中不存在答案,应低分或空召回);
9. 极短查询(单字/两字);
10. 长问句(自然语言整句)。

## 3. 指标

逐通道 + 融合方案输出:

- **Recall@5、Recall@10**;
- **MRR**;
- **无答案误召回率**:无答案题 top-5 出现任何块的比例;
- **延迟**:单查询 p50/p95;
- **索引大小**:FTS 表字节数 / 源文本字节数;
- **短词失败清单**:两字词、极短查询的逐题成败;
- **通道独有召回**:某通道单独命中而其他通道漏掉的金标准块数;
- **融合新增召回**:RRF 融合相对任一单通道的新增命中数;
- **错误案例**:逐题记录 top-5 实际命中 vs 金标准,附原因分类(分词错误/结构未过滤/同义/噪声)。

## 4. RRF 参数记录纪律

- RRF 常数 `k`、各通道权重、候选截断深度(top-N)必须**显式记录**在探针输出与实验报告中,不允许只记"用了 RRF";
- 任何参数调整 = 一次新实验记录(参数 + 全量指标),不得覆盖旧结果;
- 默认起点:`k=60`,两通道等权,候选深度各 50;调参只基于 dev 集,holdout 只在最终评估用一次(见 `evaluation-dataset-design.md`)。

## 5. 探针边界

- 语料:`experiments/` 下的测试文档子集(经 manual-markdown 或解析契约入库的 content_blocks 导出),不含任何真实学生数据;
- 分词器只用 Node 内置 `Intl.Segmenter('zh',{granularity:'word'})`,不引入第三方分词库;
- 探针结论仅决定"未来业务检索采用哪条通道",本轮业务闭环(S1)不依赖 FTS:证据检索走 SQL 元数据 + 精确匹配的最小实现。
